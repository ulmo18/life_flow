# 공통 디자인 적용 기준

반복적인 화면별 수정 요청을 줄이기 위한 구현·검수 기준이다. 사용자가 명시적으로 요청한 변경을 우선하며, 아래 기준은 같은 역할의 UI를 만들거나 수정할 때 기본으로 적용한다.

## 기준 컴포넌트

| 역할 | 기준 | 구현 위치 |
| --- | --- | --- |
| 입력 바텀시트 | 할 일 페이지의 할 일 추가 | `ui-standard-sheet`, `ui-form-sheet`, `ui-form-sheet-header`, `ui-form-sheet-actions` |
| 단일 선택 | 계획 수정의 상태 버튼 | `ui-choice-button` (radio의 표시 span 또는 `aria-pressed` button) |
| 펼치기 화살표 | 실제 일정 수정의 생활 기록·메모 | `ui-disclosure`의 8px 선형 chevron |
| 길게 누르는 작업 | 할 일 수정의 삭제 | `btn btn-ghost ui-delay-button`, 기존 1.5초 홀드 처리 |
| 알림 저장 | 해당 설정 영역 전체 너비 | 공유 알림 컴포넌트의 100% 너비·48px 최소 높이 |

시트는 최대 680px, 좌우 전체 너비, 위쪽만 둥근 모서리, 공통 안쪽 여백, 공통 표면 색과 그림자를 사용한다. 값은 `ui.css`의 `ui-standard-sheet` 토큰에서 바꾼다. 실제 일정의 고정 헤더/버튼과 내부 스크롤은 기능상 유지하되 외곽·헤더·여백 기준은 같다. 키보드가 열리면 가시 영역 안에 닫기/저장이 남아야 한다.

선택 버튼은 상태 버튼과 같은 배경·테두리·선택 색·반경·높이를 사용한다. 같은 역할의 버튼을 페이지별 색상이나 `btn-secondary` 변형으로 다시 정의하지 않는다. 지연 작업을 이동 링크처럼 꾸미거나 방향 화살표를 붙이지 않는다. 펼치기 아이콘은 문자 `^`를 별도로 넣지 않고 `ui-disclosure`를 사용한다. 모션 감소 설정도 공유한다.

상태 선택은 계획 수정/할 일 상태 시트 모두 `ui-status-row`의 한 줄 6개 배치를 쓴다. 아이콘과 짧은 이름을 세로로 묶고, 44px 타깃과 작은 가변 간격을 유지한다. 다른 선택 영역의 열 수는 기능에 맞게 유지한다. 실제 일정 연결 해제는 사용자가 요청한 보조 작업이므로 투명·작은 보조 글자로 강조를 낮추되 1.5초 보호는 유지한다.

실제 일정 추가/수정은 `_actual-time-range.php`의 시작·종료 2열과 소요 시간 배지를 공유한다. 태그 제목 우측에 새 태그를 두고, 함께 기록하기의 하위 영역은 카드 대신 가로선으로 구분한다. 실제 일정 수정은 삭제와 저장을 하단 한 줄에 20:80으로 배치한다. 라벨은 보통 굵기로 표시하고 모든 필드의 시작선을 맞춘다. 삭제의 위치/표현이 달라도 공통 홀드 보호는 유지하고 자동 비교 검사에서는 보호용 스타일을 비교한다.

## 수정 절차

1. 수정할 요소의 역할과 위 기준을 먼저 대응시킨다.
2. 같은 공통 클래스에 연결한다. 기능상 배치 차이만 해당 페이지에 둔다.
3. 덮어쓰는 로컬 규칙이 있는지 확인한다. 기존 사용자 작업을 건드리지 않으며, 이번 변경과 관련된 중복 정의를 정리한다.
4. 요청한 화면 외에도 공유 요소를 사용하는 화면을 함께 확인한다.
5. 좁은 화면·다크 테마·선택/비선택·접힘/펼침·긴 제목·키보드 축소에서 실제 화면과 계산 스타일을 확인한다. 확인하지 못한 항목을 완료로 표시하지 않는다.

## 자동 비교 검사

`tests/browser/sheet_design_parity.cjs`는 인증된 격리 QA 앱과 CDP Chrome을 사용한다. `LIFEFLOW_QA_DATE`는 계획 블록과 실제 일정이 있는 날짜, 전체/계획 알림은 켜진 테스트 계정을 준비한다. 페이지 조작은 시트를 열고 테마를 바꾸는 검수용 동작이며 데이터를 저장하지 않는다.

- `LIFEFLOW_QA_BASE_URL`: 기본 `http://127.0.0.1:18081`
- `LIFEFLOW_QA_CDP_URL`: 기본 `http://127.0.0.1:9225`
- `LIFEFLOW_QA_DATE`: 필수 `YYYY-MM-DD`
- `LIFEFLOW_QA_OUTPUT`: 화면/JSON 저장 폴더 (생략 시 OS 임시 폴더)
- 실행: `node tests/browser/sheet_design_parity.cjs`

검사는 할 일 추가를 기준으로 계획/실제 일정 시트 5종의 너비·여백·모서리·배경·그림자를 비교하고, 상태/알림 선택 버튼, 지연 버튼, 펼치기 아이콘, 알림 저장 너비, 키보드 축소 시 버튼 위치를 검사한다. 320/390/1024px × 밝은/어두운 테마를 확인한다. 일반 동작 회귀 검사는 기존 `tests/*.test.js`를 실행한다.

## 적용 기록 (2026-11-10)

요청한 알림 저장 너비, 계획/실제 시트 외곽, 관리 지연 버튼, 알림 선택 버튼, 펼치기 아이콘을 공통 기준에 연결했다. 캘린더/할 일에 흩어진 지연 진행 표시와 실제 일정의 로컬 chevron 정의를 공통 CSS로 이동했다. DB·저장 API·알림 계산·1.5초 보호 동작은 변경하지 않았다.

변경 파일: `AGENTS.md`, `app/Views/components/plan-reminder-fields.php`, `app/Views/pages/calendar/index.php`, `app/Views/pages/todo/index.php`, `public/assets/css/components/ui.css`, `public/assets/css/pages/calendar.css`, `public/assets/css/pages/todo.css`, `tests/browser/sheet_design_parity.cjs`, `docs/common-layout.md`, `docs/calendar-feature-implementation.md`, `docs/design-consistency-checklist.md`, 이 문서.

검증 결과: JS 29개 파일, 수정 PHP 3개 문법 검사, `git diff --check` 통과. 격리 SQLite 앱과 Chrome에서 5종 시트 × 3개 너비 × 2개 테마의 30개 계산 스타일 비교, 선택/비선택 버튼, 전체 너비 저장, 화살표, 할 일 삭제 대비 지연 버튼, 공통 배경 처리 및 키보드 축소 검사 통과. 화면/JSON은 로컬 `storage/unified-sheet-qa/2026-11-10/`에 보관했다. 실제 기기의 키보드/터치 감도는 별도 수동 확인 항목이다.

수동 확인: 할 일 추가와 계획/실제 일정 추가·수정을 연달아 열어 외곽·헤더를 비교한다. 계획 수정에서 알림을 펼쳐 상태 버튼과 선택 디자인 및 저장 너비를 비교하고, 관리를 펼쳐 표준 지연 버튼을 확인한다. 알림/관리/생활 기록/메모의 화살표를 비교한다. 좁은 화면, 다크 테마, 키보드를 연 상태도 확인한다.

## 메뉴 상단 탭 기준

상단 메뉴 탭의 배치 기준은 회고다. ui-menu-context는 별도 배경 없이 스크롤 고정, 날짜와 탭의 간격, 전체 너비와 탭 12px 안쪽 여백을 관리한다. 내부 날짜 행도 배경 없이 표시한다. ui-segmented-tabs는 같은 너비 버튼·선택·포커스 표시를 관리한다. 할 일·회고·반복 할 일·루틴 관리·목표·메모는 이 조합을 재사용하고 메뉴별 중복 여백을 추가하지 않는다. 상세 기준과 검수는 menu-tabs-unification.md를 따른다.

## 검색 날짜·월 선택 (2026-11-13)

검색 상세 조건은 `ui-disclosure`를 사용한다. 날짜 범위는 일정 수정 시간 필드의 두 칸 배치·48px 높이·입력 테두리·포커스 기준을 따른다. 루틴과 회고 발행 이력의 월 탐색은 `ui-month-search`, `ui-month-dialog`, `components/month-picker.js`를 공유한다.

검증: PHP 5개 문법 검사, JS 33개 파일, 공백 검사 통과. Chrome 320/390/1024px에서 상세 검색 토글, 날짜 두 칸 정렬과 가로 넘침 없음, 월 선택 창 12개 선택지, 월 선택 시 제출·루틴 상태 유지 확인. 실제 기기의 날짜 입력 UI와 다크 테마는 수동 확인 항목이다.

## 날짜·시간 선택 및 검색 상세 (2026-11-13)

날짜/월/시간 선택은 좌우 외부 여백 없는 최대 680px 하단 다이얼로그를 사용한다. 검색 날짜는 할 일 헤더의 LifeFlowDatePicker를 재사용한다. 실제 일정 시간 선택은 components/time-picker.js로 공통화했으며 HH:mm 옵션을 가진 select에 data-time-picker를 붙인다. 취소 시 원래 값 유지, 닫기 후 포커스 복귀, 부모 시트 키보드 처리 차단을 함께 확인한다. 검색 결과 상세는 전체 본문을 안전한 텍스트로 표시하며 원본 이동은 팝업 버튼으로 제공한다.

## 닫기 아이콘 (2026-11-13)

모든 바텀시트의 닫기는 일정 수정 기준인 22px × 아이콘·44px 터치 영역·가운데 정렬을 공유한다. ui-close-button과 날짜/시간/월/검색 상세의 lf-date-close는 ui.css의 --ui-sheet-close-icon-size를 사용한다. 날짜·월 이동 화살표와 텍스트 닫기 버튼은 별도 역할이다.

검증: PHP 루틴 뷰 문법, JS 33개 파일, 공백 검사 통과. Chrome 320/390/1024px × 밝은/어두운 테마에서 9가지 닫기 버튼 문맥의 계산 크기(22px/44px), 루틴 월 선택이 같은 컨텍스트 안에서 탭 위 6px 간격으로 배치됨, 경고 문구의 danger 색상·말풍선 동작·일반 확인창에 경고가 남지 않음을 확인했다.

수동 확인: Android Chrome에서 일정·할 일·목표·메모·루틴·날짜/시간 시트의 닫기를 비교한다. 실제→계획 드래그와 수정 시트 링크 양쪽에서 붉은 안내 및 ! 주의사항을 확인한다. 루틴 활성/완료 탭 전환 후 월 선택·이전/다음 달·스크롤 고정을 확인한다.
