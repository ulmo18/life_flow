# 디자인 통일 실제 앱 검수

검수일: 2026-11-10 (Asia/Seoul)

## 환경과 범위

실행 중인 Docker에서 PHP 8.2를 확인하고 별도 검수 컨테이너와 SQLite DB를 생성했다. 현재 소스 복사본과 테스트 계정으로 검수했으며 기존 개발 DB·계정은 변경하지 않았다. Chrome headless를 실제 HTTP 앱에 연결해 검수했다. 샘플 HTML 렌더링과 구분되는 결과다.

| 비로그인 화면 | 로그인·가입 × 5개 너비 × 두 테마, 20개 조합 |

주요 경로는 대시보드·회고·루틴·할 일·일정·반복 할 일·루틴 관리·목표·목표 회고·메모·검색·설정·태그와 로그인 리다이렉트다. 기본 너비는 320/360/390/430/1024px, 데이터 화면은 320/390/1024px다. 시트는 320/390px 너비와 844/500px 높이로 검사했다. 검사 범위에서 가로 넘침이 없었고 시트의 닫기 버튼은 화면 안에서 44px 너비를 유지했다. 주요 페이지와 입력 시트, 로그인·가입 화면의 캡처를 확인했다.

실제 CSRF 폼으로 회원가입·로그인을 수행한 뒤 다음 14개 저장 흐름을 확인했다: 목표 생성/수정, 루틴 생성/수정, 할 일 생성/수정, 메모 생성/수정/휴지통 이동/복원, 태그 생성/수정/삭제, 테마 저장 및 새 페이지에서 유지. 폼 POST와 응답·목록을 확인한 것으로, 모든 버튼의 포인터·키보드 상호작용 전수 검증을 뜻하지 않는다.

## 발견 및 수정

루틴 입력 시트에서 스크롤한 필드가 고정 헤더 위의 19px 틈으로 보였다. `.routine-sheet.ui-standard-sheet .routine-sheet-header`의 고정 위치를 시트 여백의 음수 값으로 맞추고 헤더 여백·패딩을 동일하게 적용했다. 실제 페이지에서 헤더 상단이 패널 상단과 일치하며, 입력 시트 40개 조건이 재검사를 통과했다. 읽기 전용 상세의 기존 표면은 유지한다.

## 복합 데이터·키보드 추가 검수

12단계 목표 트리, 한 계획에 연결된 여러 실제 기록, 연결 루틴과 완료 목표, 긴 KPT가 있는 실제 발행 보고서를 별도 SQLite 환경에 구성했다. 모델·서비스 API로 검수 데이터를 만들었다.

- 전체 목표·완료 목표 회고·발행 보고서·발행 이력의 40개 기본 너비/테마 조합에서 페이지 너비와 요청 뷰포트 너비를 비교했다. 의도적인 목표 관계도 내부 스크롤은 페이지 넘침과 구분했다.
- 전체 목표·완료 목표 회고·발행 보고서를 320/390/1024px, 두 테마, 기본/두 배 글자 크기로 검사한 36개 조합에서 페이지 가로 넘침·자동 축소가 없었다. 글자 확대는 각 요소의 계산된 글자 크기를 두 배로 적용한 검사이며 실제 OS 글자 설정과 같지는 않다.
- 실제 키 이벤트로 목표 상세의 초기 초점, 마지막 컨트롤에서 Tab 순환, 첫 컨트롤에서 Shift+Tab 순환, Escape 후 원래 목표 버튼으로 초점 복귀를 확인했다. 연결 기록이 있는 상세 패널도 390px 화면 안에 유지됐다.
- JS 회귀 테스트는 목표 초점 경계·숨겨진 컨트롤 제외·중첩 창 우선순위 검사를 추가해 25/25 통과했다. 변경된 목표 PHP 뷰도 구문 검사를 통과했다.

깊은 트리를 펼쳤을 때 모바일 Chrome의 레이아웃 뷰포트가 558px까지 넓어지면서 전체 화면이 작아지는 문제를 발견했다. 관계도 자체를 가로 스크롤 영역으로 만들고 행 최소 너비를 280px로 확보해 해결했다. 이전의 문서 너비와 `innerWidth`만 비교하는 검사는 이런 자동 축소를 놓칠 수 있어 요청한 뷰포트 너비와도 비교하도록 검수 스크립트를 보완했다.

목표 상세/수정에 초기 초점·Tab 경계·초점 복귀가 없던 부분도 보완했다. 목표 추가의 닫기/ Escape에서도 생성 버튼으로 돌아온다. 날짜 선택기나 공통 확인창이 열리면 상위 목표 창의 키보드 처리보다 우선한다.

추가 캡처와 JSON은 `storage/design-qa/2026-11-10/complex/`에 보관한다. 검수 계정·컨테이너는 정리한다.

## 공통 입력 접근성 추가 검수

메모 작성·루틴 관리 생성·일일 루틴 빠른 추가를 320/390/1024px의 실제 앱에서 검사했다. 9개 조합 모두 초기 내부 초점, Tab/Shift+Tab 경계 순환, 공통 확인창에서 Escape 시 하위 시트 유지, 하위 시트 종료 후 원래 버튼 복귀를 통과했다. 메모 수정과 루틴 수정/상세는 같은 열기·닫기 코드를 사용하지만 모든 데이터 상태를 실제 키 이벤트로 전수 검사한 것은 아니다.

공통 확인/입력창도 Tab 경계를 처리하고 Escape 전파를 중단한다. 이 처리로 아직 독립적인 Escape 핸들러를 사용하는 다른 페이지에서도 중첩 확인창과 배경 시트가 동시에 닫히지 않는다. 입력값과 저장 요청은 변경하지 않았다.

공통 밝은 테마 placeholder는 보조 글자색을 사용해 표면색 기준 측정 대비가 약 2.48:1에서 5.68:1로 개선됐다. 오류 글자색은 `#a7443c`로 조정해 오류 배경에서 약 4.32:1에서 5.06:1로 개선됐다. 두 테마의 placeholder 실제 계산 색상이 보조 글자색과 일치함을 Chrome에서 확인했다. 초점 테두리는 불투명 primary-text 색을 사용한다. 이 수치는 지정한 공통 토큰 쌍의 측정값이며 그라데이션·투명 레이어·사용자 태그 등 모든 화면의 접근성 인증을 의미하지 않는다.

기존 테스트와 새 시트 키보드·공통 토큰 대비 회귀 검사를 포함해 JS 테스트 27/27이 통과했다. JSON 결과는 `storage/design-qa/2026-11-10/accessibility/`에 보관한다.

## MySQL 호환 환경 추가 검수

MariaDB 10.11과 PHP 8.2를 별도 Docker 네트워크·컨테이너로 실행하고 `sql/schema.mysql.sql`을 적용했다. DB는 임시 메모리 저장소를 사용하며 기존 개발용 MariaDB와 볼륨에 연결하지 않았다. SQLite 검수와 동일한 12단계 목표·다중 연결 실제·루틴·완료 목표·긴 발행 회고를 모델/서비스 API로 생성했다.

- 대시보드·일정·할 일·루틴·루틴 관리·반복 할 일·전체 목표·목표 회고·발행 보고서·메모·검색·설정·태그의 13개 실제 페이지 × 5개 너비 × 두 테마, 130개 조합에서 페이지 가로 넘침과 자동 축소가 없었다. 깊은 관계도의 의도적인 내부 가로 스크롤은 허용했다.
- 실제 CSRF POST로 목표 생성/수정, 루틴 생성/수정, 할 일 생성/수정, 메모 생성/수정/휴지통 이동/복원, 태그 생성/수정/삭제, 테마 저장 후 유지의 14개 흐름이 통과했다. 복원은 휴지통의 응답뿐 아니라 활성 메모 목록에서 내용이 돌아온 것까지 확인했다.
- `calendar_block_migration_mysql.php`의 연결별 임시 테이블 스냅샷 검사도 통과했다. `retrospect_try_links_mysql.php`는 DB 이름을 제한하는 자체 안전 가드에 따라 실행되지 않았으며, 가드를 우회하지 않았다. 모델/서비스를 통한 실제 MySQL 발행 보고서 생성·렌더링은 별도로 위 범위에서 확인했다.

추가 소스 수정이 필요한 MySQL 화면·저장 차이는 발견되지 않았다. 이번에는 검수 문서만 갱신했다. MariaDB에서 수행한 MySQL 드라이버 검수이며 Oracle MySQL 8 자체의 실행 검증과 동일하지는 않다. 결과와 캡처는 `storage/design-qa/2026-11-10/mysql/`에 보관한다. 임시 DB·앱·브라우저·네트워크는 정리한다.

## 나머지 일일·관리 시트 키보드 검수

할 일·반복 할 일·일정의 남은 시트에 Tab 경계와 닫기 후 초점 복귀를 적용했다. 일정은 기존 이동/범위 선택 취소와 내부 선택 화면 돌아가기를 유지하며, 별도 계획 추가 시트도 Escape로 닫는다. 메뉴가 숨겨져 원래 버튼을 표시할 수 없으면 일정의 빠른 메뉴 버튼으로 복귀한다.

실제 앱에서 할 일 추가·수정·상태, 반복 할 일 추가, Plan 블록 추가, 일정 메모·실제 편집·계획 추가의 8개 흐름을 320/390/1024px에서 검사했다. 총 24개 조합에서 초기 내부 초점, Tab/Shift+Tab 순환, Escape 후 복귀, 요청 뷰포트 너비 유지가 통과했다. Chrome Accessibility 트리에서 검사한 비무시 버튼·텍스트 입력·콤보박스·체크박스·라디오에 비어 있는 접근성 이름은 없었다. 이름의 의미·읽기 순서·모든 보조기술 동작을 인증한 결과는 아니다.

회귀 테스트의 시트 키보드 검사를 할 일·계획·일정까지 확장했으며 전체 JS 27/27과 변경 파일 구문 검사를 통과했다. 결과는 `storage/design-qa/2026-11-10/remaining-sheets/`에 보관한다. PATH 및 기본 Android SDK 경로에서 adb/에뮬레이터 도구가 확인되지 않아 실제 기기 검증은 수행하지 않았다.

## 남은 확인

- 실제 iOS/Android 키보드·안전 영역·PWA/WebView 및 글자 확대. 높이 500px 에뮬레이션은 실제 키보드 검증을 대체하지 않는다.
- 스크린 리더, 모든 조작의 키보드 탐색·초점 복귀·명도 대비 전수 검사.
- 그 밖의 다양한 사용자 데이터 조합과 모든 조작의 전수 검증. 발행 보고서·다중 연결·12단계 목표 트리의 Chrome 검수는 위 추가 검수에서 수행했다.
- 실제 알림 수신·기기 권한·재부팅 복원. 이번 디자인 검수 범위 밖이다.
- Oracle MySQL 8 자체의 실행 검증. MySQL 드라이버의 MariaDB 10.11 실화면·저장 검수는 위에서 완료했다.

검수 캡처와 JSON은 로컬 `storage/design-qa/2026-11-10/`에 보관한다. 해당 경로는 Git 추적 대상이 아니다. 테스트 계정과 DB는 검수 컨테이너 정리 시 함께 제거한다.

## 수동 재검증

1. 두 테마에서 목표·루틴·할 일·메모·태그의 빈 목록과 데이터가 있는 목록을 확인한다.
2. 루틴 생성/수정을 열어 폼을 끝까지 스크롤한다. 헤더 위에 필드가 보이지 않고 닫기·저장에 접근 가능한지 확인한다.
3. 모바일 키보드를 연 채 입력·저장·닫기를 수행하고 안전 영역과 글자 확대를 확인한다.
4. 추가·수정·삭제 후 목록, 새로고침 후 설정 유지, 메모 휴지통 복원을 확인한다.
