# 실제 일정 시트 레이아웃 적용

2026-11-10. 제안 시안의 시간·태그 배치와 가벼운 가로선 구분을 추가/수정 시트에 함께 적용했다. 기존 공통 색상·타이포그래피·시트 외곽·닫기·펼치기 아이콘을 유지했다.

## 변경

- 시간: 시작/종료를 같은 너비의 두 입력으로 표시하고 각 입력 안에 라벨과 시계 아이콘을 배치했다. 시간 제목 우측의 소요 시간 배지는 선택한 10분 인덱스 차이로 즉시 갱신한다. 기존 값/필드명, 시간 충돌 검사, 종료 24:00 지원은 그대로다. 두 시트가 `_actual-time-range.php`를 공유한다.
- 태그: 제목 우측의 `+ 새 태그`에서 기존 인라인 편집기를 연다. 새 태그는 선택되고 다른 시트에도 반영된다. 버튼이 legend 안으로 이동한 점에 맞춰 편집기 검색/새 태그 삽입 기준을 수정했다. 태그 칩은 줄바꿈되며 긴 이름은 칩 안에서 생략한다.
- 함께 기록하기: 생활 기록·메모·실행력 및 루틴 선택 행의 카드 배경과 둥근 모서리를 제거하고 가로선으로 구분했다. 요약/선택/저장 동작은 유지한다. 펼친 입력은 본문 너비 안에 유지한다. 연결된 계획은 관계를 나타내는 옅은 표면으로 구분한다.
- 삭제/저장: 삭제를 기록 영역 밖, 스크롤 본문 마지막의 보조 텍스트 동작으로 옮겼다. 기존 1.5초 홀드 보호는 유지한다. 저장만 하단 고정 영역에 남겼다.
- 회전한 펼치기 화살표가 본문 끝을 2px 넘쳐 가로 스크롤을 만들던 부분도 예약 열 안에 정렬했다. 시간 입력 포커스는 컨트롤 안쪽에 표시한다.

## 검증

- JS 31개 파일 및 수정 PHP 3개 문법 검사, `git diff --check` 통과.
- 소요 시간 40분, 종료 24:00, 하루 전체, 잘못된 범위의 안내 표시를 회귀 검사했다.
- 격리 SQLite 앱과 Chrome에서 실제 시간표 빈 칸으로 추가 시트를 열고 시간 변경·새 태그 생성/취소·다른 시트 반영·새 일정 저장·수정·메모/태그 유지·재열기를 확인했다.
- 삭제를 짧게 누르면 실행되지 않고, 1.5초 이상 누르면 실행되는 것을 새 본문 위치에서 확인했다.
- 320/390/1024px × 밝은/어두운 테마 × 추가/수정의 12조건에서 같은 너비 시간 입력, 제목 옆 태그 추가, 투명한 기록 행, 펼친 메모 너비, 페이지 넘침 없음 확인. 추가로 접힘/펼침 및 입력 포커스에서 본문 내부 가로 스크롤이 없는지 확인했다.
- 공통 시트 스타일 비교와 키보드 축소 검사를 수행했다. DB/스키마/API/시간 저장 정책은 변경하지 않았다. 실제 Android 네이티브 선택 UI는 별도 기기 확인 항목이다.
- 화면/JSON은 로컬 `storage/actual-sheet-layout-qa/2026-11-10/`에 보관한다. 기존 개발 DB는 변경하지 않았다.

## 수동 확인

1. 빈 실제 시간 칸으로 추가 시트를 열고 12:10–12:50을 선택해 40분 배지를 확인한다. 시작/종료 변경과 24:00 종료도 확인한다.
2. 제목 옆 새 태그에서 취소 및 생성을 확인한다. 생성한 태그를 선택한 채 저장하고 수정 시트에서 그대로인지 확인한다.
3. 생활 기록·메모·실행력을 펼쳐 가로선 구분과 요약, 입력/저장 유지 여부를 확인한다.
4. 수정의 삭제와 저장이 하단 한 줄에 20:80으로 배치되는지 확인한다. 짧은 삭제 누르기는 실행되지 않아야 한다.
5. 좁은 화면/다크 테마/키보드가 열린 상태에서 닫기·저장 접근성과 가로 넘침을 확인한다.

## 수정 시트 정렬 보정

이 보정이 위 초기 배치 기록보다 우선한다. 수정 시트의 일정명·시간 그룹의 배경과 추가 안쪽 여백을 제거해 태그·기록 행과 시작선을 맞췄다. 라벨은 13px 보통 굵기, 필드 간격은 space-4, 라벨과 입력 간격은 space-2로 통일했다. 삭제·저장은 고정 하단 1:4 열이며 기존 1.5초 삭제 보호를 유지한다. 추가 시트는 유지한다.

변경 파일: `app/Views/pages/calendar/index.php`, `public/assets/css/pages/calendar.css`, `docs/common-layout.md`, `docs/design-system-contract.md`, 이 문서.

검증: JS 31개 파일, PHP 문법, 공백 검사 통과. 이번 보정의 브라우저 시각 검수는 수행하지 않았다. 수동 확인: 320/390px와 다크 테마에서 라벨 정렬·기록 펼치기·키보드 표시 시 하단 버튼 접근성, 삭제 짧게 누르기와 1.5초 홀드 동작을 확인한다.

### 연결 계획 카드 복원

수정 시트의 연결 계획에만 덮어쓰던 투명 배경·가로선 규칙을 제거했다. 추가/수정이 동일한 surface-soft 배경, radius-md, 12px 안쪽 여백을 공유한다. 변경 파일: `public/assets/css/pages/calendar.css`, 이 문서. 수동 확인: 실제 일정 수정에서 연결 계획은 배경 카드로, 함께 기록하기는 가로선으로 구분되는지 밝은/어두운 테마에서 확인한다. 실행력 안내는 직접 입력 모드에만 표시하는 기존 조건을 유지한다.
