# 실제 일정 → 계획 전환

## 확정된 규칙과 구현

오입력 수정이 목적이다. 실제 블록을 계획 시간표로 드래그해 놓으면 저장 직전에 **계획 일정으로 전환** 확인창을 연다. 확인 전·취소 시에는 저장하지 않는다. 수정 시트에도 작은 보조 텍스트 링크 모양의 전환 버튼을 유지한다. 링크는 저장된 날짜·제목·시간을 사용하며, 아직 저장하지 않은 편집은 반영하지 않는다고 안내한다.

- 새 전환은 시간 미정 할 일 원본과 같은 시간의 계획 블록을 만든다. 중요도는 D, 상태는 미정, 알림은 기본 꺼짐이다. 실제 위치가 있으면 새 할 일에 복사한다.
- 이미 정확한 계획 블록에 연결된 실제 일정은 그 계획을 재사용하고 해당 실제 기록만 제거한다. 드래그 전환이면 기존 계획의 시간을 드롭 범위로 바꾸고, 시트 링크 전환이면 원래 시간을 유지한다. 블록 없는 할 일에 연결된 경우는 그 원본을 재사용하여 실제 시간의 블록을 만든다. 기존 할 일의 상태·제목·중요도·위치는 덮어쓰지 않는다.
- 실제 일정은 소프트 삭제하면서 메모·태그·계획 연결을 비운다. 해당 실제 일정의 실행력 설정·생활 기록·위치 행을 제거한다. 실행력은 활성 실제 기록에서 계산되므로 재조회 시 해당 사용량이 제외된다.
- 연결된 기존 계획·할 일은 중복 생성하지 않는다. 계획 시간 충돌, 다른 사용자, 삭제된/시간 없는 Actual은 거부한다. 재전송도 새 복사본을 만들지 않는다.
- 생성·삭제·부가정보 제거는 한 DB 트랜잭션에서 처리한다. MySQL은 날짜 행과 실제 일정을 잠그고 재조회해 경쟁 요청을 직렬화한다. 실패하면 원본 및 부가정보와 계획 생성 모두 되돌린다.
- 드래그와 시트 링크 모두 같은 명시적 확인·저장 함수를 사용한다. API는 CSRF와 discard_actual=1을 요구한다. 진행 중 저장/삭제/중복 전환을 막고, 실패 시 기존 컨트롤 상태를 복원한다. 성공 시 해당 날짜의 계획 화면으로 돌아가 Toast를 표시한다.

## 범위의 경계

루틴 완료는 날짜별 독립 기록이며 어떤 실제 일정에서 완료했는지의 출처가 없어 전환만으로 되돌리지 않는다. 이미 발행된 회고는 저장된 스냅샷 정책을 유지한다. Try 연결은 원본 실제 일정이 삭제된 경우 기존의 사용 불가 표시 정책을 따른다. 새 알림 예약 취소·로그아웃 정리 기능은 사용자의 요청에 따라 추후 작업으로 남긴다.

## 수동 확인

1. 계획이 없는 시간에 메모·태그·실행력·생활 기록·위치를 가진 실제 일정을 만들고 다시 연다. 전환 확인을 취소하면 모두 유지되어야 한다.
2. 확인 후 같은 시간 계획과 할 일이 나타나고 실제 기록은 없어야 한다. 새 할 일의 위치는 유지되고 실행력/생활 기록/메모/태그는 넘어가지 않아야 한다.
3. 같은 시간에 이미 계획이 있으면 전환은 거부되고 실제 기록을 유지해야 한다.
4. 기존 계획에 연결된 실제 기록은 전환 후 원래 계획만 유지하며 중복 계획/할 일을 만들지 않아야 한다.
5. 작은 화면과 키보드가 열린 상태에서 확인창, 취소 후 복귀, 통신 실패 안내와 재조회 결과를 확인한다.

## 실제 → 계획 드롭의 시간 처리

Actual 내부 이동은 기존 경로를 유지한다. Plan 위에서는 같은 길이의 범위를 미리 표시한다. 잡은 블록 지점의 시간 오프셋을 유지해 대상 범위를 계산하고, 놓는 순간의 실제 좌표를 다시 검사한다. 다른 칸/화면 밖에 놓거나 pointercancel이면 미리 보기를 지우고 저장하지 않는다. 같은 시각이라도 Actual에서 Plan으로 넘어가면 전환 확인을 보여준다.

드롭 확인창은 목표 HH:mm~HH:mm과 실제 부가정보 삭제, 기존 연결 계획의 시간 변경을 명시한다. API의 선택적 start_index/end_index는 0~144 범위의 유효한 정수이며 DB에 저장된 Actual 길이와 같아야 한다. 길이가 바뀐 오래된 화면/잘못된 요청, 목표 시간 충돌은 트랜잭션을 취소한다. 연결 계획을 옮길 때는 그 블록만 충돌 검사에서 제외하고 다른 계획은 검사한다.

시트의 전환 버튼은 배경·테두리·화살표를 제거한 12px 보조색 밑줄로 표시한다. 동작 의미는 button으로 유지하고 44px 터치 영역과 키보드 포커스 표시를 유지한다. DB 마이그레이션은 없다.

## 전환 확인창의 안내 계층

전환 범위와 질문은 줄바꿈한 굵은 문장으로 표시하고 문장 끝의 느낌표 버튼으로 주의사항 말풍선을 연다. 모바일 탭·키보드 Enter/Space로 고정 열기/닫기를 할 수 있고, 마우스 hover로도 볼 수 있다. 펼친 느낌표에서 Escape는 말풍선만 닫으며 다음 Escape는 기존 확인창 닫기를 따른다. 말풍선은 작은 보조색 글머리표 목록이다. 드래그는 삭제 영향·기존 연결 계획의 시간 변경·새 계획의 제목/위치 기준을 표시하고, 시트 링크는 미저장 편집 안내도 표시한다. 일반 확인창은 기존 텍스트와 버튼 배치를 유지하고 이 형식을 사용하는 전환 확인창만 작은 화면에서도 취소·전환 버튼을 같은 너비의 한 줄로 유지한다. 네이티브 confirm 대체 경로에는 질문과 모든 주의사항을 줄바꿈해 제공한다.

검증: JS 33개와 PHP footer 문법·공백 검사 통과. Chrome의 320/390/1024px에서 두 테마 및 합성 마우스/터치 포인터로 질문 강조/줄바꿈, 주의사항 초기 접힘·탭/hover/키보드 닫기, 글머리표, 50:50 한 줄 버튼, 취소 시 요청 없음, 일반 확인창으로 돌아갈 때 상태 초기화를 확인했다. 말풍선이 열린 실제 화면도 시각 검수했다. 수동 확인: 계획 칸 드롭 후 ! 아이콘으로 주의사항을 열고 취소/전환을 비교한다. 시트 링크에서는 미저장 편집 주의사항이 추가되는지 확인한다.

## 주의사항 확인 안내 (2026-11-13)

전환 질문 아래에 붉은색으로 “전환하기 전에 ! 아이콘을 눌러 주의사항을 꼭 확인해 주세요.”를 항상 표시한다. 기존 ! 말풍선의 상세 주의사항과 50:50 취소/전환 버튼은 유지한다. 공통 confirm의 선택적 warning 문자열로 전달하며 다른 확인창에는 추가하지 않는다. native confirm 대체 경로에도 같은 안내를 포함한다.
