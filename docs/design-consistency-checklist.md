# 하루흐름 디자인 통일 체크리스트

## 목적과 사용법

현재 확정 기준은 `docs/design-system-contract.md`를 따른다. 바텀시트는 할 일 추가, 선택 버튼은 상태, 펼치기 아이콘은 실제 일정의 생활 기록/메모, 지연 버튼은 표준 삭제 버튼을 기준으로 한다. 관련 변경 후 `tests/browser/sheet_design_parity.cjs`로 공통 요소의 계산 스타일을 비교한다.

### 현재 검수 상태 (2026-11-10)

공통 디자인의 코드 적용 및 데스크톱 Chrome의 실제 앱 검수를 진행했다. Docker PHP 8.2와 별도 SQLite DB·테스트 계정을 사용했으며 기존 개발 DB와 계정 데이터는 변경하지 않았다. 상세 결과는 `docs/design-qa-report.md`에 기록한다. 실제 모바일 기기·스크린 리더·알림 수신까지 완료된 상태는 아니다.

하루흐름의 화면을 개선하거나 새 화면을 만들 때 이 목록을 복사해 사용한다. 체크는 실제 화면과 코드에서 확인한 항목만 표시한다. 이 문서는 작업 목록이며, 체크되지 않은 디자인 값이나 컴포넌트가 이미 통일되었다는 뜻은 아니다.

일정의 시간표, 할 일의 표, 발행 회고의 신문 형식처럼 작업 목적이 다른 화면의 특성은 유지한다. 공통 규칙과 다르게 표현해야 한다면 이유와 적용 범위를 기록한다. 화면 기능, 데이터, 사용 흐름은 디자인 작업만으로 바꾸지 않는다.

### 코드 조사와 적용 기록

#### 2026-11-10 추가 정리

- 할 일·반복 할 일·Plan 블록·일정 시트의 남은 Tab 경계와 초점 복귀를 보완했다. 일정 별도 계획 추가는 Escape 닫기를 지원하며 숨겨진 원래 메뉴 동작 대신 빠른 메뉴 버튼으로 복귀할 수 있다. 네이티브 날짜 선택기·공통 확인창 우선순위와 기존 이동 취소·선택 화면 돌아가기는 유지한다.
- 실제 8개 시트 흐름 × 3개 너비의 24개 조합에서 초기 초점·Tab/Shift+Tab·Escape 후 복귀·페이지 너비 유지를 확인했다. 검사한 Chrome 접근성 트리에 이름 없는 버튼/입력/선택 컨트롤은 없었다. 스크린 리더 전수 검증을 뜻하지 않는다. 확장된 회귀 테스트를 포함한 JS 27개가 통과했다.

- MySQL 드라이버도 기존 개발 DB와 분리된 MariaDB 10.11에서 현재 MySQL 스키마를 적용해 검수했다. 깊은 목표·연결 기록·발행 회고가 있는 주요 13개 페이지의 130개 너비/테마 조합과 실제 생성·수정·삭제·복원·테마 저장 14개 흐름을 통과했다. 페이지 전체 자동 축소 여부도 요청 너비와 비교했다.
- MySQL 연결별 임시 테이블 스냅샷 검사도 통과했다. 다른 Try 통합 검사는 자체 DB 이름 안전 가드로 실행되지 않았으며 우회하지 않았다. 새로운 화면/저장 결함이 없어 추가 소스 변경 없이 검수 문서와 로컬 캡처를 갱신했다. MariaDB에서의 확인이며 Oracle MySQL 8 자체·실제 모바일·스크린 리더 검증은 별개다.

- 공통 확인창·메모·루틴 관리·일일 루틴 빠른 추가의 Tab 경계와 초점 복귀를 보완했다. 상위 확인창의 Escape는 전파를 중단해 배경 입력 시트까지 닫지 않는다. 실제 9개 화면/너비 조합에서 초기 초점·순환·중첩 창 유지·복귀를 확인했다.
- placeholder는 두 테마의 불투명 보조 글자색을 사용하고, 밝은 오류 글자와 초점 테두리는 대비가 더 높은 토큰으로 맞췄다. 공통 표면 기준 placeholder 5.68:1·오류 5.06:1을 측정했다. 공통 토큰 대비와 시트 키보드 회귀 검사를 추가해 JS 27개가 통과했다. 전수 대비·스크린 리더·실제 모바일 검증을 대체하지 않는다.

- 복합 데이터 추가 검수: 12단계 목표 트리·다중 실제 연결·루틴·완료 목표·긴 KPT 발행 보고서로 기본 40개와 글자 확대 포함 36개 실제 화면 조건을 확인했다. 모바일 자동 축소를 잡기 위해 문서 너비뿐 아니라 요청한 뷰포트 너비도 비교했다. 깊은 목표 지도는 280px 최소 행 너비와 내부 가로 스크롤로 전체 페이지 축소를 방지한다.
- 목표 상세/수정/추가의 초기 초점·Tab 경계·닫은 뒤 초점 복귀를 보완했다. 날짜 선택기·공통 확인창을 우선하며 숨겨진 컨트롤은 초점 순환에서 제외한다. 실제 Tab/Shift+Tab/Escape 검사를 통과했고 JS 테스트는 25개 모두 통과했다. 세부 범위·남은 실제 기기 검증은 `docs/design-qa-report.md`를 따른다.
- 수동 검증: 전체 목표를 깊게 펼쳐 관계도만 좌우로 이동하고 헤더·하단 내비게이션 크기는 유지되는지 확인한다. 목표 상세→수정에서 Tab·Shift+Tab·Escape로 탐색하고 원래 목표 버튼에 초점이 돌아오는지 확인한다. 날짜 선택기와 삭제 확인창이 열린 경우 내부 키보드 동작을 확인한다.

- 실제 PHP 페이지 검수에서 루틴 입력 시트 스크롤 시 헤더 위로 필드가 비치는 문제를 발견했다. 표준 입력 헤더의 고정 위치를 시트 여백의 음수 값으로 맞춰 수정했다. 390px 화면에서 패널 상단 164px에 대해 헤더 상단이 183px에서 164px로 정렬되는 것을 확인하고 실제 시트 40개 조건을 재검증했다.
- 격리된 실제 앱에서 주요 경로 140개 너비/테마 조합, 레코드가 있는 화면 36개 조합, 실제 입력 시트 40개 조합, 비로그인 로그인/가입 화면 20개 조합을 검사했다. 가로 넘침과 검사한 시트의 닫기 버튼 접근 문제는 없었다. PHP 106개 구문 검사, SQLite 기준 테스트 50개, JS 테스트 24개를 통과했다.
- 실제 POST로 목표·루틴 생성/수정, 할 일 생성/수정, 메모 생성/수정/삭제/복원, 태그 생성/수정/삭제 및 테마 저장 후 유지 여부를 확인했다. CSRF를 포함한 실제 폼 값을 사용했으며 생성 데이터는 검수 컨테이너에만 저장했다.

- 공통 루틴 상태 버튼의 기본·완료·실패 표면과 테두리를 의미별 테마 색상으로 통일하고 모서리 12px·크기 44px를 적용했다. 표 안에서 잘리지 않도록 안쪽 3px 키보드 초점을 제공한다. O/X 상태 전환과 저장 값은 유지한다.
- 일정·루틴 일일/관리·회고에서 루틴 상태 CSS도 기존 수정시각 기반 자산 키로 로드한다. 다른 주요 변경 CSS는 이미 버전 키를 사용하고 있음을 확인했다.
- 검증: 실제 Node 프로세스에서 기존 JavaScript 테스트 24개 전체 통과. 루틴 상태 버튼 샘플은 5개 너비·두 테마의 10개 조건에서 44×44px, 초점 3px, 완료/실패 배경 구분 및 가로 넘침 없음을 확인했다. PHP 실행 환경이 없어 컨트롤러 PHP 실행 검증은 하지 않았다.
- 수동 검증: 루틴·일정에서 상태 버튼을 Tab/Enter로 조작하고 O/X 순환과 저장 후 유지 여부를 확인한다. 두 테마에서 상태 구분과 표 안의 초점을 확인한다. 네트워크 탭에서 `routine-state.css?v=...` 요청을 확인한다.

- 목표 집중/전체 지도와 루틴 관리/상세의 빈 화면을 공통 표면·빈 상태로 전환했다. 문구와 목표 추가·전체 목표 이동 동작은 유지한다. 공통 빈 상태의 버튼은 표면 안에서 가운데 정렬한다.
- 성공·안내·오류 메시지 테두리는 의미별 전경·배경 색상에서 파생하고 긴 문자열을 줄바꿈한다. 실제 뷰·JS·테스트 참조가 없는 이전 `.todo-create-tabs` 중복 규칙 4개를 삭제했다. 현재 탭은 공통 `.ui-segmented-tabs`를 사용한다.
- 검증: 5개 너비와 두 테마의 10개 샘플에서 빈 상태의 16px 여백·모서리와 44px 버튼, 긴 상태 메시지의 가로 넘침 없음을 확인했다. 상태 메시지 테두리의 테마별 변경도 확인했다. 실제 빈 목록·목표 추가·화면 이동은 수동 검증 대상이다.
- 수동 검증: 목표가 없는 집중/전체 화면에서 안내와 동작 버튼을 확인한다. 루틴의 활성/종료 목록 및 기록 없는 상세를 확인한다. 성공·오류 안내를 두 테마에서 확인하고 할 일 탭 전환이 유지되는지 확인한다.

- 목표 추가와 루틴 관리 생성·수정 시트를 `ui-standard-sheet`로 전환해 하단 정렬 표면·20px 여백·그림자를 공유한다. 루틴 560px·목표 620px 최대 너비와 개별 높이 제한은 유지한다. 루틴 입력 시트가 보일 때만 레이어 바깥 여백을 없애며 읽기 전용 상세의 여백·모서리는 유지한다. `:has()` 미지원 브라우저는 기존 바깥 여백을 유지한다.
- 루틴 고정 헤더·저장 영역은 실제 시트 여백을 사용하고 안전 영역을 고려한다. 목표 추가 헤더도 20px 여백에 맞췄으며 루틴 높이는 동적 뷰포트를 따른다.
- 검증: 루틴 생성·수정·읽기 상세, 목표 추가 × 5개 너비 × 두 테마의 40개 샘플을 Chrome headless로 검사했다. 입력 시트의 20px 여백·하단 정렬·하단 모서리, 상세의 기존 16px 여백·12px 바깥 간격, 가로 넘침 없음과 스크롤 후 닫기·마지막 저장 버튼 접근을 확인했다. 실제 PHP 폼 저장과 모바일 키보드는 별도 확인이 필요하다.
- 수동 검증: 목표 추가 및 루틴 생성·수정·상세를 차례로 열어 두 테마에서 표면을 비교한다. 긴 폼을 스크롤하며 닫기·저장 버튼, 모바일 키보드와 안전 영역을 확인하고 실제 추가·수정을 저장한다.

- 공통 토스트의 표면·구분선·동작 글자색을 테마 변수로 통일했다. 긴 메시지와 동작 문구가 화면 안에서 줄바꿈하고 동작 버튼은 최소 44px와 키보드 초점을 제공한다. 날짜 선택기 헤더의 긴 제목도 줄바꿈하며 닫기 버튼은 44px를 유지한다.
- 검증: 일반/축하 토스트 × 5개 너비 × 두 테마의 20개 조합에서 문서·토스트 가로 넘침, 동작 버튼 높이·초점 및 날짜 선택기 닫기 버튼 너비를 검사했다. 실제 기존 토스트 JS를 실행해 동작 콜백 후 닫기, 동작 없는 메시지의 버튼 숨김도 확인했다. Chrome의 움직임 줄이기 설정에서 축하·진행 애니메이션이 꺼지는 것을 확인했다.
- 수동 검증: 실제 앱에서 저장 안내와 되돌리기 동작을 열고, 긴 문구·두 테마·Tab 초점·동작 실행을 확인한다. 날짜 선택기 제목과 닫기 버튼, 모바일 안전 영역 및 글자 확대를 확인한다.

- 설정 테마 선택과 알림 그룹에 공통 14px·굵기 600 라벨 및 테마 표면을 적용했다. 테마 선택은 선택 배경과 키보드 초점을 제공하며, 긴 번역 문구는 열 안에서 줄바꿈한다. 네이티브 라디오·체크박스의 동작은 유지한다.
- 할 일·일정 공용 중요도 라디오는 44px 높이, 공통 입력 테두리·모서리와 3px 초점 표시를 사용한다. 시간 입력은 줄어들 수 있는 동일 너비 열로 배치하고, 할 일 시트 높이는 동적 뷰포트와 기존 `vh` 대체값을 사용한다.
- 검증: 설정·중요도·시간 입력 샘플을 320·360·390·430·1024px 및 두 테마의 10개 조합으로 Chrome headless에서 검사했다. 긴 영문 알림 문구에서도 가로 넘침이 없고 중요도 높이 44px·초점 3px·테마 선택 배경 구분을 확인했다. 실제 기기 키보드와 설정 저장·알림 실행은 확인하지 않았다.

이 표는 현재 적용한 컴포넌트 기준이다. 모든 화면의 실기기·접근성 검증 완료를 뜻하지 않는다. 코드 적용 기록과 샘플 렌더링 검증은 위 기록을 따르며, 아래 화면별 완료 확인은 실제 앱에서 별도로 진행한다.

아래 값은 기존 CSS 변수와 화면을 조사하고 대표 화면에서 검증한 뒤 확정한다. 새 값을 임의로 화면마다 추가하지 않는다.

- [ ] 글꼴, 크기 단계, 굵기, 줄 높이와 숫자 정렬 기준을 정한다.
- [ ] 기본·보조·비활성 텍스트, 배경, 표면, 구분선, 강조, 오류·성공 색의 용도를 정한다.
- [ ] 화면 좌우 여백, 섹션 간격, 라벨과 입력창 간격, 목록 행 안쪽 여백을 단계별로 정한다.
- [ ] 카드·입력창·버튼·바텀시트의 모서리와 테두리, 그림자 사용 기준을 정한다.
- [ ] 아이콘의 종류, 크기, 정렬과 의미를 정한다. 색상만으로 상태를 구분하지 않는다.
- [ ] 기존 `app.css`의 색상·간격 등 변수를 재사용하고, 부족한 의미별 변수만 공통 위치에 추가한다. 라이트·다크 테마를 함께 정의한다.
- [ ] 결정된 값과 용도, 적용 예외를 이 문서 또는 별도 디자인 기준 문서에 기록한다.

## 3. 공통 컴포넌트

- [ ] 헤더: 제목·날짜·검색·메뉴 버튼의 높이와 정렬을 맞추고, 날짜가 필요 없는 화면은 빈 공간을 남기지 않는다.
- [ ] 탭: 높이, 간격, 선택 표시와 텍스트 크기를 맞춘다.
- [ ] 버튼: 기본·보조·강조·위험·아이콘 버튼의 역할과 선택·비활성·포커스 상태를 정한다. 링크도 같은 역할이면 같은 모양으로 표시한다.
- [ ] 표와 목록: 행 높이, 좌우 여백, 구분선, 긴 이름 말줄임과 행 내부 버튼 정렬을 맞춘다. 할 일 표를 기준 후보로 검토한다.
- [ ] 카드: 배경·테두리·간격을 역할별로 정리하고, 단순 목록을 불필요한 카드로 감싸지 않는다.
- [ ] 입력: 라벨과 입력창의 정렬·간격, 높이, 도움말·오류 표시, 포커스 상태를 맞춘다. 날짜 선택은 기존 공통 달력을 우선 사용한다.
- [ ] 바텀시트: 제목과 닫기 버튼, 본문 여백, 내부 스크롤, 키보드 대응과 하단 고정 주요 동작을 맞춘다. 태그는 기존의 선호 디자인을 기준 후보로 검토한다.
- [ ] 빈 상태·로딩·오류·토스트: 같은 상황에서 표현과 행동을 일관되게 제공한다.
- [ ] 새 컴포넌트는 기존 공통 컴포넌트로 해결할 수 없는 경우에만 만든다. 공통 구현과 사용 예시, 필요한 변형을 기록한다.

## 4. 적용 순서

- [ ] 기준 화면에서 글자·간격·색과 주요 컴포넌트를 먼저 적용하고 실제 화면을 검토한다.
- [ ] 공통 헤더와 바텀시트, 버튼·입력창을 우선 정리한다. 기존 기능과 다른 페이지에 미치는 영향을 확인한다.
- [ ] 할 일·루틴의 목록과 빈 상태를 통일한다.
- [ ] 일정의 시간표·블록과 태그, 회고의 신문 형식은 고유한 표현을 유지하면서 공통 기준을 적용한다.
- [ ] 반복 할 일·목표·메모·검색·설정 등 나머지 화면을 순차적으로 적용한다.
- [ ] 페이지별 중복 스타일은 실제 사용처와 우선순위를 확인한 뒤 정리한다. 관련 문서와 사용 예시를 함께 갱신한다.
